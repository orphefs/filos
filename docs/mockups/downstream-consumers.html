Who does this change reach outside the repo?

Filos looks for downstream consumers with GitHub code search, at review time, with no index and no clones. Filos runs the searches. The agent judges each match and may ask for a few more searches. It never gets network access itself. These screens use the bundled sample PR, so every repo and line here is example data.

Filos searches first, without asking the agent. It searches for every changed exported symbol, plus the package name (repos that depend on @acme/ledger). For services it would also search HTTP routes, protobuf messages and topic names.
The agent asks; Filos decides. Each round the agent may propose up to 4 follow-up searches. Filos checks that each one stays inside the scope and the budget, then runs it. The agent itself never reaches the network.
Visible and capped. Every search shows who asked for it. The search and file-read budgets show at all times. Cancel stops the step without losing the graph.

Consumers on the graph, each with a verdict

Each confirmed consumer becomes a node, with the agent's verdict on it. Matches the agent rejected, such as a vendored copy or a mention in docs, are counted but stay off the graph.

Downstream impact drives the risk colour, which CLAUDE.md lists as the top signal. A confirmed consumer counts in full; an "unaffected" one adds nothing.
Verdicts are worded as outcomes: breaks, changes behaviour, unaffected. They need wording that's easy to scan. This is a first proposal.
Default branches only. Code search sees each repo's main branch, not open branches. The graph says "found by search" so nobody reads it as complete.

Why

Line 41 calls roundToCents(subtotal * rate) without a mode. After the upgrade, a total that lands exactly on a half cent rounds to the even cent: 12.5¢ becomes 12¢, not 13¢. Carts and the invoices from this PR then agree, but only once both are upgraded.

Decisions for you

  1. When it runs. Automatically after the graph (as shown), or only when you click "Look downstream"? Automatic gives the fullest picture; on-click saves searches and tokens.
  2. Budget defaults. 12 searches, 30 file reads, 3 rounds, up to 4 follow-ups per round. More finds more but takes longer and costs more tokens. GitHub's code search allows about 10 searches a minute.
  3. Verdict words. Breaks, Changes behaviour, Unaffected, plus a confidence. Or: Breaking, Affected, Safe. Or a 0–1 impact score.
  4. Questions wait for it? As shown, questions wait for the downstream findings so they can ask about them. Or write questions at once and add downstream questions later.
  5. Privacy notice. Snippets from other repos go to Claude Code or Codex. Show a one-time notice per org, or rely on the README? The scope is your own org by default.
